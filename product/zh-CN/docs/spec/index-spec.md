# 索引与读取规范

## 1. 职责与入口 <a name="entry"></a>

- 根 INDEX 定位根文件、D 和已采用资料层。局部索引管本域对象，正文沿各自入口取用。D 的身份取 #bindings。
- INDEX 管位置、对象身份、读取方式及必要字节登记；config 管实例选择与官方来源；HANDOFF管实际现场、三态、任务和消费记录。索引登记本身不授予写入、联网、通信或执行权限。
- 先由根 INDEX 进入所属 INDEX。治理、配置、章程及现场的启动检查取根治理；先检查再读受保护正文。
- 下文的“根”指本实例由用户确认的工作区根；章程生效后由HANDOFF.root定位。根路径不授予根身份；材料阶段按用户实际打开位置识别，不用空root猜路径。
- INDEX 的入口列以该 INDEX 所在目录为路径基准。跨文档的稳定引用按 #refs 解析；确需物理路径的工具参数，从所属索引取得。

## 2. 索引模型 <a name="model"></a>

### 2.1 根 INDEX：六列 <a name="root"></a>

| 字段 | 含义 |
|---|---|
| # | 表内连续阅读顺序，不承担持久身份 |
| 标识 | 所属索引内唯一的稳定身份 |
| 名称 | 面向人的简短名称，使用实例选定语言 |
| 类别 | 文件、目录或索引等实际对象类型 |
| 入口 | 目标实际位置；使用可点击的短标签链接 |
| 取用方式 | 起始位置、读取范围和必要的继续定位方法 |

根索引保留governance、handoff、config、projects、docs及T等实际用途；docs是D的唯一入口，不再另增D行或rule-*规范别名表。K／R／M按实际选择登记，未启用不预造入口。最小组合为根入口＋D＋T；projects是业务用途，D是本区文档域，均不另造资料层仓库。

根 INDEX 的 fieldcase_version 仅为 config 同名权威值的受控展示；采用章程和核心升级收尾时同步核对。普通定制不改来源号，两处不符时先核明来源，不按数字大小选边。根 INDEX 不再记录 locale、governance_adoption 或另一份路径配置；采用方向取 config，不以入口形状推断。

### 2.2 局部 INDEX：七列 <a name="local"></a>

文档区、K／R／M／T 及必要下级索引复用根六列，只增加“体积”列，放在入口与取用方式之间。

以下为字段示意，示例目标不是现行登记对象：

```markdown
| # | 标识 | 名称 | 类别 | 入口 | 体积 | 取用方式 |
|---|---|---|---|---|---|---|
| 1 | example | 示例对象 | 文件 | [示例](example.md) | 实际 B | 可整读，或写明检索入口与限制 |
```

- 文件体积使用实际 UTF-8 文件的 B 字节数；不能用字符数、行数或估算 KB 代替受保护文件的 B 值。
- 目录等不适用项填“—”；动态目录不为取一个总数而递归统计。受保护目录的逐文件记录仍须齐备。
- 可否整读、单片大小、查询命令及返回限制合入取用方式，不另加“可整读”列。允许整读某个文件或单片，不表示允许整读整个目录。
- # 每张表从 1 连续排列；同一 INDEX 分表时接续编号。重排时可重编 #，持久引用仍用标识。
- 文件入口的局部路径相对其所在目录，目录入口的局部路径相对该目录；取用方式另有明确基准时照登记执行。
- 自建 K／R／M／T 推荐先按用途或归属建立一级分类，内容放入相应分支，分支内再按实际需要细分。例如 M 的 `media/images/covers/` 依次是媒体、图片和封面集合。单一、易于查找的集合可以保持浅层，分类名称与深度按实际用途决定。
- 这四层的总 INDEX 登记实际一级分类，以及已准入的层根治理和其他固定入口文件。普通分支通过目录路径或按需设置的局部索引指向下一层，内容明细由所属分支定位。专用索引沿其已准入协议。


复用已存在的上级共享层时，保留其已准入索引协议，不将八列等现有格式强改为七列。接入方案须按列名明确标识、入口、逐文件 B、读取范围及维护权的对应关系，并核实全部有效引用。自行新建的本区索引仍用本规范模型；原件和本地导航不能冒充共享层现行登记。

### 2.3 层的内容身份 <a name="identity"></a>

本区新建的 K／R／M 层在自己的 INDEX 记录以下字段；内容版本与固定来源按实际管理范围和来源记录。复用外部共享层时沿其真实内容身份，不补造 baseline、分支或层版本；采用来源及协议差异记本区 HANDOFF。docs、T 不为导航另设层版本。

| 字段 | 含义与取值 |
|---|---|
| layer_version | 本份 INDEX 及其正文的精确内容版本 |
| content_state | development为当前建设／开发内容；baseline为经明确准入且有可靠固定定位的消费基线；released为实际已落版内容。三者不替代工作区生命周期 |
| development_branch | 对应开发分支；无适用分支时为 null |
| stable_ref | 已确认稳定基线的固定标签或定位；尚无可核实定位时为 null |

包内版本及内容身份仅为材料默认值，不表示实例已成立或完成。实际采用按已准入章程及真实内容维护；新层无可靠固定基线时为development、stable_ref=null，不因章程落盘、待开工或首提交自动设baseline。固定消费基线须核完整内容、准入及定位，不能冒充普通落版；旧原件和历史中的身份按其固定来源读取。

开发 INDEX 的入口、成员和 B 值描述该开发来源；读取正式旧版要取旧版自己的 INDEX。层 INDEX 不记消费者、不记自身提交 ID。候选试用不改变层本来的 development 身份。

## 3. 稳定标识与路径解析 <a name="refs"></a>

### 3.1 标识规则 <a name="keys"></a>

- 标识在所属索引内唯一，保持简短可辨识；同一对象改名、迁移或排序后保持标识。撤销的标识不另给新对象使用。
- D／K／R／M／T前缀是文档定位记法，不是操作系统盘符或可直接执行的命令；工具调用先按索引解析实际路径。
- D:<标识>先从本区根INDEX的docs项进入D总INDEX，再查所属条目；K／R／M／T分别从实际登记的对应层进入。D不加入资料层配置，前缀及所属标识不得互代；未启用K也不影响D解析。
- 不同工作区的同名前缀按其已明确的根及来源解析；跨区文档或回执先绑定所属区，不把上位文件中的D／K引用改成本区入口。引用不改变身份、权属或实施授权。
- D:agent-guide定位操作指南，D:upstream定位实际留存的采用原件，D:backups仅在形成物理恢复快照时登记。原件、历史、恢复资料不因位于D就成为现行规范，不全量重读。
- 引用可接 #<局部定位键>；文件入口后接数字表示行号或行号范围，其他局部键由取用方式解释。例如 D:index-spec#1-6 读取本文件第 1–6 行，T:audit#my-project/ 定位审计分类内已授权项目目录；数字行号与下列规范章节短 ID 分别解析，不将旧章号当作行号。
- 本区现行规范用D:<规范标识>#<章键>引用，资料或提供侧规范仍按其实际所属前缀；规范内部用#<章键>。真实章节标题末登记`<a name="<id>"></a>`，先定位实际文件再读同名锚点，示例标题不登记；不预建具体设计规范，也不按相近章号猜补章键。
- ID 以小写字母开头，使用短词或可辨识简写，可含数字与连字符，文件内唯一，不照抄完整标题；章号、标题或顺序变化时保持 ID。更换 ID 须同批修正有效引用，旧 ID 不复用为其他含义。
- 表格行不会自动生成 Markdown 锚点。需要人直接点击到条目时，维护真实的页内锚点或现有标题锚点，不以一个不存在的 #标识声称链接可用。

### 3.2 路径边界 <a name="paths"></a>

- 入口列的链接目标即实际路径，是唯一登记的入口。上级沿已登记的目录入口或下级索引继续定位，文件路径和 B 值由所属索引维护一处。
- 本区新建文件、仓库及迁入当前内容默认限定目标根内。已存在的上级共享层可按完整接入方案从根 INDEX 引用根外入口；不以 ../、外部绝对路径或符号链接绕过未授权边界。
- 共享接入按实际使用对象核对来源层、维护权、真实 INDEX、协议、固定来源和读写边界。实际引用了章键就核对该章键，缺项按 #read 处理，受保护对象按 #guard 核完整成员和逐文件 B。需要派生物理配置时使用已确认的实际入口。
- 方向1的本区管理判据从 D 现行规范和根治理读取。共享规范的章键沿其实际适用范围使用，索引格式对应只解决外部对象定位。适用上位规则与本区管理要求发生冲突时，接入由采用方按根治理 §1.6 处理。
- 外部共享层保持既有位置与维护权；本区不复制其层根或代建仓、不改其总索引。获准的临时／贡献产物只进入所属共享层已明确授权的本区归属路径，不擅建第二套实际 T。
- 从旧工作区接入，默认建议复制清单内内容、按采用方向对齐治理，再于目标原地建仓；源根、源仓及旧治理分别保留溯源。目标成果须按本次清单独立核实，不沿用源状态、旧initialized或父仓识别结果。
- 只有用户明确强制要求移动原实例时，才按专门授权处置源目录，并核对根定位、实际仓根及受影响物理配置；不重做已有有效文档、复制或仓库。只切换会话不重跑采用问卷或重建目标。
- 不借复制、索引变更或共享接入切换源实例既有仓库布局。名称和深度可在获准范围定制，实体、入口、权限和派生配置配套核对。
- 治理正文优先写稳定引用；固定启动文件、治理自身权威位置、已准入迁移清单和不能解析标识的工具配置可使用必要物理路径。

### 3.3 D文档定位与现行规范 <a name="bindings"></a>

D 由根 docs 定位。D 总 INDEX 唯一维护本区入口、类别、B 和取用范围。不设 layer_version、content_state、development_branch、stable_ref 或资料 pin；随本区准入与根仓维护。

| D标识 | 职责与生效条件 |
|---|---|
| index-spec | 本区索引、来源与保护模型；方向1及接入阶段必需 |
| handoff-spec | 本区交接、三态、版本与接续模型；方向1及接入阶段必需 |
| design-spec | DESIGN的组织与维护模型；方向1及接入阶段必需 |
| cache-spec | 已采用知识获取模块的方法规范，未选不装 |
| contract-spec | 已采用跨区协作模块的方法规范，未选不装 |

规范统一位于本区D的专用spec目录，默认docs/spec/；自建K或复用外部K都不改变此位置规则。不并行维护K/spec和D/spec两套本区工作规范。根只登记docs入口，不维护rule-*别名表，不在config新增路径或绑定字段。

解析D:handoff-spec#state时先保存章键，再由docs入口到D总INDEX的handoff-spec行、实际文件和B，最后定位state；目录入口的后续局部坐标按登记方式继续，不回根重解同名局部标识、不循环绑定或猜旧路径。索引维护实际页内锚点供点击。

D现行规范按本区当前已准入状态读取，资料消费pin不换读本区规则。已适用上位治理与规范仍按其有权指定来源执行；K可以保存技术或提供侧规范，归在K不自动降低其原有约束。采用原件和恢复快照不作现行规则。

方向2按已准入自治实现及单一采用记录办理，不因缺D或改目录推断自治。旧实例升级须同批迁移现行规范、有效引用、目录保护和所属索引；原件、固定来源和历史按原结构保留，不长期维护两套独立别名。

## 4. 选定一次读取的来源 <a name="source"></a>

- 默认消费策略取 config.consumption.default_strategy；实际采用的来源与接续事实取消费区 HANDOFF 的资料依赖记录。改默认值不改写已经进行中的任务。
- shared-development：新任务或明确采用更新时，固定一个已准入、已提交的开发提交；该任务始终从这个提交读取 INDEX、成员清单和正文。
- stable：采用本区记录的正式固定基线；比较审阅不改变依赖。实际试用须明确层、候选提交、适用范围和原正式依赖，并在同一消费记录处补充。
- 同任务中断、换会话或上下文变化后，恢复原固定来源；采用更新要明确切换，不能把恢复当作自动跟进 dev 或 main。
- 按实际所属仓定位来源。同一仓内受控的根 INDEX、相关层 INDEX 和正文从同一固定提交取得，路径也按该提交解析。不同来源分别核对。分支用于找到提交，移动的分支名本身不是固定快照。
- 可按确定提交直接只读文件，不要求切换维护者工作目录。人工点验确需文件目录时再按需展开到 T，不预建所有历史版本副本。
- 本区无仓不等于所有来源无 Git；外部独立来源已有可核实提交或固定副本时按实际固定。无可靠历史定位的来源记录本地现状与读取范围，不声称提交快照、历史 pin 或分支隔离；后续变更重新核对受影响部分。
- 所选提交自身的 INDEX 才是其文件树的配套登记；不能用旧 INDEX 核对当前工作树，也不能因维护者有未提交改动就认定已固定提交不可读。

## 5. 受保护对象核对 <a name="guard"></a>

### 5.1 范围展开 <a name="targets"></a>

config.index_guard.layers只列实际采用的K／R／M，D不写入该数组。D现行规范及专用目录始终按#core-guard检查；未采用资料层且未增加额外目标时，layers和targets可同时为空，不关闭D保护。

保留已准入自定义保护能力：targets的file／directory可指已登记的D现行工作文档／专用目录或资料对象，pattern默认在所选资料层展开。D核心不靠这些条目启停；额外D目标须有真实入口、类型、B或完整成员，不把整个docs、原件、历史和恢复批次自动视为现行规范。无资料层但有额外D目标时，layers可空、targets按实际填写。

按实际已采用的资料层治理、规范及规范目录生成file／pattern／directory目标，保留已准入自定义目标。实际没有适用资料保护对象时可为空，须在方案说明依据；存在应保护对象却漏列、层身份不明或引用无效时不能以空数组放行。不预设K:specs等提供侧未登记标识。

| 目标类型 | 实际检查范围 |
|---|---|
| pattern | 所选层固定来源中匹配文件名模式的受控文件 |
| file | 稳定引用解析到的精确文件 |
| directory | 真实目录标识，或已登记文件引用后接#./所确定的所在目录及完整子树 |

#./只在directory目标中表示具名文件的所在目录，例如K:index-spec#./。先从同源INDEX定位真实index-spec文件，再取其父目录；它不是章键、行号或层总INDEX所在目录，也不支持任意#../路径跳转。普通规范章节仍按#<章键>解析。

派生目录必须在所属D文档域或资料层的获准边界内，具备同源完整树或可靠目录依据，全部受控成员须有所属索引的实际入口及逐文件B。只取得文件或部分成员时不记目录级通过。不能由章号、常见目录名或目录总大小推断范围。

采用章程或明确变更保护方案时，列明已采用规范及规范目录，生成既有file／pattern／directory目标；保留用户已准入自定义目标。提供侧没有目录标识但有真实规范文件及完整树时可使用上述#./，不改其INDEX造标识。根部单个治理／设计文件按file保护，不因此默认把整个资料库根纳为规范目录。

同一来源同对象重复命中去重；读取时不因提供侧出现新条目自动扩大授权或改配置。成员、来源或B缺口按#errors处理。

### 5.2 必要检查 <a name="checks"></a>

下列固定来源五项用于资料对象；额外D现行工作对象按本区当前准入来源、D条目与真实文件参照#core-guard核对，不要求新增D资料pin。两种用途分开记录来源，不跨来源合并去重。

1. 固定来源存在，身份、内容版本与消费记录相符。
2. 层入口、对象类型、目标引用和实际目录可解析。
3. 受保护目录的完整成员可由所属索引定位；增、删、改名和挪位均与登记一致。可复用已有索引，不因每层目录再建一个 INDEX。
4. 每个受保护文件的实际 B 值与该来源登记相同。
5. 核对期间只读取文件清单、类型和必要字节信息；通过后，治理与规范在触发重读时按根治理全量读取，其他正文按任务与登记范围读取，不为检查整读知识库。

Git 固定来源的受控成员从该提交树取得；不把未提交或未跟踪文件混入所消费快照。无 Git 时按当前已确认文件范围核对，明确系统／仓库项不属于内容的依据；新出现的内容成员不能静默当作系统项忽略。

不做文件哈希验证。相同 B 值只能证明长度登记相符，不证明正文未变，不代替准入、来源核实和版本控制。正文修改后要核对索引；B 与其他登记均未变时，不强造 INDEX diff、流水号或时间戳。

### 5.3 差异处理 <a name="errors"></a>

| 错误码 | 情况 |
|---|---|
| SOURCE_REF_INVALID | 固定来源不存在，或其身份与记录不符 |
| INDEX_ENTRY_MISMATCH | 缺登记、入口缺失、类型不符、成员增删或位置与索引不符 |
| INDEX_BYTES_MISMATCH | 所选来源实际 B 值与登记不符 |

报告至少含错误码、层与标识、固定来源、实际入口、登记值／实际值、受阻任务及建议核实方。常态开启 enforce 时，中断该层访问并停止当前任务，保留现场；不继续依赖该规范实施。

消费会话不直接将 B 改为现场值来消除错误。由根或所属维护者按权限判断索引漏更、对象移动还是未准入改动，拟修缮方案并按授权落实。修复提交后，消费方明确采用修复来源并复验。

enforce=false 仅按根治理允许解除既定索引偏差的强制阻断；仍做轻量检查并报告差异。来源不可核实、必要文件不可达、配置损坏和缺少实施授权仍是实际缺口。never-ask 只控制修缮后的恢复提醒，不改变读取或写入权限。

### 5.4 实例规范的保护 <a name="core-guard"></a>

D:index-spec、D:handoff-spec、D:design-spec及实际已采用模块规范的专用目录常态纳入保护；核心三项不可因删索引行、未选K或清空资料层／模块配置退出。D不是新增资料层，不另设开关；沿现有enforce、restore_prompt及排障权限办理。

读正文前按根治理 §1.3 核根 docs、D 的真实规范条目、权限、来源、逐文件 B 与专用目录完整成员。三核心都须可达。未建仓或无 Git 采用准入候选、清单和现场依据，不补造提交；旧资料 INDEX 不证明现行规范。

实际目录成员与所属INDEX登记对照，不用检查时临时生成的实际清单自证完整；缺核心条目、缺文件、循环、越界和未登记成员按现有错误码报告。不因B相同宣称正文未改，不增加文件哈希验证。

管理规范与任务资料各按其来源和用途核对；同源同对象去重，不跨来源合并或拿资料副本作治理。外部层按 #guard 及实际协议。

本区规范修改获准后由其维护者同步正文、D条目B、完整目录及必要引用；读取时发现差异不自动补B。删除或移动规范先按准入方案处理有效引用和保护，未完成不得宣称升级、卸载或接入完成。

## 6. 渐进读取与结构差异 <a name="read"></a>

- 由总 INDEX 找到所属分支，再沿目录入口或局部索引逐级定位。大库按标题、稳定键、路径或查询工具限量检索，再按命中读取正文。未标可整读时，不据文件名猜测整读许可。
- 已按目录分级的单库仍有大量明细时，可对它的局部索引分片，按任务限量读取。
- 查无标识时报告未登记，不猜旧路径；规范章键缺失时报告缺口，不按相近章号推定；命中后正文缺失时报告缺口，不用搜索摘要或未读内容代替原文。
- 访问层根与登记路径时，核对可消费分区和规范入口。仓库／系统项、已有分区内普通业务内容变化，不自动等同于新增治理分区。
- T只核对已登记分类，分类下项目／任务／批次增减不算新增公共分类。D的原件版本、恢复批次和历史卷沿已登记入口渐进取用，不因新增批次强制全量扫描；现行规范文件及规范目录变化仍须同批登记。
- 可消费分区或规范入口新增、缺失、改名或迁移而未同步登记，停止当前任务并报告；未裁定前不自行补索引或搬动文件。
- 历史卷、旧官方原件和升级备份按登记定向读取，不参与现行治理的全量重读和保护扫描。历史中的路径按当时状态理解，不批量改写。

## 7. 维护与迁移 <a name="maint"></a>

- 根维护者管理本区根 INDEX、docs INDEX 及本区拥有的 T 总 INDEX；外部共享 T 和其他层的 INDEX 继续归所属维护者。消费方只读取。可访问、发现问题或有工具不等于获准修改。
- 新对象或入口变更先拟登记和必要迁移；取得执行授权后，实体、索引和派生配置同批更新，再验证引用可达。
- 文档目录整体移动而内部不变时更新根 docs 入口；指南在文档区内移动时更新 docs INDEX。层入口和局部对象依此分工，不在所有正文复制可变根路径。
- 配置不保存 paths 副本；Git 忽略、工具参数等物理配置不解析稳定标识，迁移时须从最终入口重新派生并验证。
- 索引校验包含条目标识与规范章键各自唯一、类型真实、入口及章节可达、成员登记、B 值、取用限制和跨文档引用；未经核实不记为通过。
- 索引修改不扩大内容准入。K 生产、R 快照和 M 材料的写入边界分别取所属治理；选装模块只在实际采用、配套核验完成后进入现行入口。

## 8. 权威与复核 <a name="auth"></a>

本规范以D:index-spec为本实例主题权威；根docs入口定位D总INDEX，后者维护实际文件和B。根治理规定授权及最短启动检查，指南解释操作，不另立第二套模型。变更先拟稿、准入后实施，并同步有效引用；复核触发见元数据。
