## 2. 按需形成的入口

下表说明条件，不代表原件、快照、历史或材料已经存在。实际形成后在§1登记真实标识、类别、入口、B及读取范围，接续编号。

| 对象 | 建立条件和登记内容 |
|---|---|
| cache-spec／contract-spec | 对应模块实际采用时，从固定原件安装到本区spec并核验完整配套；作为D现行规范登记 |
| upstream | 实际保存采用或比较原件时登记，默认upstream/fieldcase/。原件按精确版本或候选批次区分，核实语言、保存范围和包内相对结构。现行采用的定位维护见§3 |
| migration | 实际形成来源副本、复制清单或核验材料时登记，不预建固定日志类，不以旧原件替代新生效治理 |
| distribution | 共享T无分发分类且本区实际保存固定包材料时，登记其资源INDEX；不擅造上级公共分类 |
| backups | 只有实际生成必要文件快照时登记默认backups/<日期>/<升级批次>/；批次INDEX在snapshot外，保持本次范围和真实结构。Git恢复记录足够时不强制建此目录 |
| handoff-history | 实际阶段归位或落版登记形成后登记，根L1由HANDOFF.history进入，本区文档索引／卷按版本定位 |
| handoff-pending | 有真实未排期细节时按稳定标识定向取用，不预建空件 |
| pitfalls | 有实际问题和证据时建立，与交接B段同号，不常态整读 |

## 3. 维护与取用

D不等于全部规范。只按已生效范围全量重读治理及规范；指南按任务取用，采用原件、历史、恢复批次按需定向读取，不把整个docs递归纳入启动保护。

指南和规范的物理位置及B在本表唯一维护；整个D位置改变由根docs项更新。不复制rule-*根别名或config路径表。文件名继续使用*-spec.md，稳定标识和章键保持；移位与真实引用、保护及配套同批核验。

D:upstream 用于取得三方比较的原件。实际采用后，只在 upstream 行的「取用方式」记录当前核心及每个已采用模块所用的确切原件入口。模块按标识区分，路径以该行入口目录为基准，可指向同一固定包的实际清单，再定位各对象。同号候选以随包 README 登记的整包批次区分，按 D:agent-guide §5.1 核实；配套材料来源不作整包批次。config 记录来源版本，原件入口在此维护。比较原件可并列保留，现行定位仅随已经完成并核验的采用、升级或停用更新。

D:backups 只定位实际文件快照，恢复依据和清单的要求取根治理 §6。Git 足够、未形成快照时，恢复定位及清单记已有方案或 HANDOFF。

原件、唯一证据和恢复依据的清理沿各自授权，不能因新命名、Git可用或下载新版而删除旧件。权威和权限按所属治理，不由D前缀或文件名自动产生。
