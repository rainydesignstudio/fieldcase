# fieldcase · 中文资源包

fieldcase 是一套由 Agent 带你新建、复制迁入和接手工作区的底座。根入口管规则、导航、配置和交接；D 放文档和现行规范，T 放临时产物；K／R／M 按需采用。各层职责见 §2。

## 1. 开始入口

用这份随包 README 开始，告诉 Agent 目标工作区和想先做的一件小事。你为本次会话选定的工作目录也可以作为目标；目标不必事先创建。Agent 先核实目标，与资源包所在目录分开。你不用预填选项或另写引导提示。

- 首次采用：从本 README 开始，带一个空目标和一件小任务，就走首用；明确只要求审阅或已有获准方案要接续时除外。目标尚不存在或只含未生效的材料／模板时，同样适用。Agent 按下方入口读取指南 §1.1 正文。工作区语言未确认时，发 [1] 前必须读取本 README 同一资源根的 [AGENTS.md](AGENTS.md) §2.5 正文。第一条实质回复按该节发起语言选择。用澄清工具发题后等你的实际答复。只有你说没看到才同题重发一次，重发后仍看不到才给等效文字选项。没有可用澄清工具时直接给等效文字选项。语言已确认时，接问第一个未决的必需项。
- 方案与授权：把小任务列进完整方案，和章程一起交你审定；小任务草稿不能代替首问。只有你审定并明确授权后，Agent 才在获准范围写入或开工。
- 接手：已有生效章程或获准方案需要接续时，按目标的实际文件和授权接手。
- 只读审阅：你明确只要求阅读、核对或在会话里拟稿时，Agent 只交所求的结果，不发起首用问答。想先走首用、暂不写入，仍可在会话里作答和审方案。

Agent 从[根索引](INDEX.md)定位[根治理](AGENTS.md)、[交接](HANDOFF.md)和[配置](config.json)，经 [docs 入口](INDEX.md#docs)进入 D 索引，以 agent-guide 定位指南。开始、审阅和接手的具体分流见 D:agent-guide §1.1。实际目录和 K／R／M／T 引用按所属 INDEX 解析。

这是 fieldcase 0.1.0.0 中文资源包，含 12 份核心，以及 K／R／M 和三个模块的 10 份配套材料。配置和根索引中的 0.1.0.0 是资源来源号。请把包解到独立目录，按上述入口开始；实测范围、后置事项和许可见 §5。

整包批次：`fieldcase-0.1.0.0-zh-CN-menu-01`；包语言：`zh-CN`。此批次标识这份完整资源包。K／R／M 和模块配套材料的来源另见分发索引；仅拿到解包文件时，也从这份随包 README 核对整包批次。

基础使用需要 Agent 宿主有实际本地读写能力；选择 Git 时需有本地 Git。不要求另装项目、外部 Skill、MCP、专用运行时或登录 GitHub。能力不足时说明缺口及可用的人工办法，未测事项按实际情况记录。

### 1.1 极简起步

第一件事可以是写一份入口说明，告诉后来人从哪里开始，并核通其中一条引用。想用最小组合时，可在澄清中选择根入口＋D＋T、无 Git、仅核心及所选层必要规则。请按实际需要作答；这里的示例不会替你确认任何选项。

小任务随章程一起列入方案。只授权章程写入时，落盘后先停在待开工；同一次授权若也包含这个小任务，就按原目标号开工并验证成果。换新会话接手时见 §1.3。

### 1.2 取得资源后准备章程与开工

1. 确认语言，核对对应的固定版本资源；自制用户包与源码归档分开。正式下载地址以已核实的官方发布入口为准。
2. 确认从零新建或复制迁入，并选定完全按 fieldcase 管理，或保留私有采用原件并由区内部分／全部治理自治。不从旧定制或原件留存推断采用方向；按方案保留名称、业务事实及开放配置。迁入默认先复制、再对齐治理、最后在目标原地建仓（如选 Git），源区保持；强制移动须另有明确授权。
3. 由 Agent 按指南核对来源、目标、身份、组成、路径、配置和 Git；已有可靠答案直接复用。采用方在目标落实所选治理并核实实际外部依赖。
4. 在会话审阅完整方案和章程稿，确认目标版本。获文档授权后，留存采用原件，集中写入章程和必要配套；章程首次生效且具体工作还没开始时是待开工；准备过程不另设状态或开关。
5. 环境、依赖、业务复制、Git 建设或小任务实际开始时进入开发中，沿用同一个目标号。中断只补剩余；阶段完成不退回待开工，实际落版与公开发布分别放行。

模板的 locale 和 governance_adoption 留空，分别表示语言和采用方向尚未确认。中文资源和初始 D／T 材料不替用户作答。所选语言或层材料缺失时按指南核对，不静默改选。

### 1.3 已有实例的接手

把实际工作区根交给新会话。Agent 按根治理重读适用文件和当前交接，核对目标版本、状态、分支、来源、已有成果和未尽项，再按有效授权接续。已有结果不重做，已确认的选项不重问。新任务须明确范围和完成条件；无 Git 时如实说明历史和隔离能力。

## 2. 组成与职责

| 组成 | 用途 |
|---|---|
| 根入口 | AGENTS管权限，HANDOFF管当前工作集及三态，config管选择及官方来源，INDEX管导航 |
| D | 本区文档与现行规范，从根docs进入；规范在本区spec，不随K位置切换，不独立设仓／层号／pin |
| K，可选 | 实际知识库，可自建、引用共享或按批准清单导入，不为核心制度强建空层 |
| R／M，可选 | 参考快照／证据、生产材料，沿实际协议和权限 |
| T | 按归属存临时产物及未启用材料，不独立建仓；共享T不复制或增公共分类 |

D 总 INDEX 登记三核心规范的入口、类别及 B。依 D:标识取用，无须另建根别名。提供侧与上位规范按实际适用范围生效。

D:upstream 原样保留确切采用原件；取得材料不构成采用。升级的恢复依据取 §4 及根治理，常规备份沿实际落版规则。

## 3. 模块与以后发现能力

| 模块 | 提供什么 | 配套 |
|---|---|---|
| 知识获取 | 获取、转换、索引及可选验证的方法 | D方法规则与T缓存；正式产出须有已准入K目标，不自带业务库 |
| 跨区协作 | 契约、联络、推送及相应边界 | contract-spec、契约入口及根治理模式配套；安装不授权发送 |
| 无人值守 | 无人值守预检、任务 heartbeat、连续迭代及可另行启用的熔断复活 | 根治理配套、交接事实及 T 审阅入口；安装不启动任务，实际采用须有兼容材料与宿主能力 |
| 项目内 Skills | 对实际模块的可选入口封装 | 同一权威和兼容基线；不强制外部全局安装，不预定数量 |

独立布局的选装原件从T的distribution定位fieldcase/INDEX.md；共享T无此分类时，按docs索引登记的固定包资源入口定位，不为本区增设公共分类；先读该索引，再读其 adoption 配套说明。资源齐备不代表启用：包内默认只登记D／T，资料保护层和modules为空，不表示用户已选极简；实例的实际采用以现行根 INDEX 和 config 为准。采用按用户选择、兼容核对、治理准入和执行授权办理，成功后才记录精确来源，不另在 README 维护来源清单。

业务出现缺口时，先检查本地能力与说明，再询问是否联网查看兼容官方材料。可只装兼容模块、评估完整升级或保持现状，不强制追新、不默认轮询。

常用讨论入口：讨论：简图看字符／Markdown结构预览；讨论：可视化看宿主可视预览；讨论：拟稿审完整文档及diff。图类型UI保留，权限及能力边界取根治理，预览不等于实施或验收。

## 4. 定制与更新

根和局部 INDEX 集中维护路径。config 记录核心及模块来源版本，D:upstream 定位实际采用的原件。同号候选也须找到确切批次。HANDOFF 维护本地工作集版本、三态和实际资料依赖。

按实际采用方向比较原件、现状和新原件，由用户审定差异。先按根治理 §6 核每项改前来源；Git 足够时保清单，缺口补快照。失败按项恢复。核验文件和配套后再更新实际来源。

方向1按fieldcase规则和已开放配置维护，不以区内整件替代实现自治；方向2可部分或全部自行实现治理，明确采用范围及维护责任。升级不强制追新、不静默切换方向，也不承诺任意定制自动兼容。完整操作见 Agent 指南，规则模型由治理与规范承担。

## 5. 实测范围与限制

包内交接与配置都是待填写的模板。选装材料随包提供。解包和阅读不会建立实例或启用模块；提交普通选项不代替明确的执行授权。

早期隔离试验分别采用了固定的中文候选。

- 首用与接手：在隔离、无 Git 的目标中，真人完成首次引导并点验小文档任务；新会话能凭实例文件找到待办，并在获得明确授权后续写。另有只读接手样例。全量重读、待审状态有流程偏差，授权前审阅完整差异未验证，均保留原记录。
- Git 与迁入：分别验证了从零建仓、同号开发分支，以及一次本地试验落版的主干快进、备份、归档和状态转换；另一例用旧答卷完成复制、治理对齐和知识库保留，源副本保持，迁入目标无 Git。
- 原件与恢复：独立样例验证了同版本号原件的准确定位，以及用 Git、必要快照或两者结合做定向恢复。早期两种采用方向、仓库布局和选装配套仍按各自样例的覆盖范围取证。

现场试用覆盖三种情形。

- 空区开工：章程落盘并点验入口，新会话凭实例文件只读接手。现场形成了真实小项目的方案及接续任务。
- 复制迁入：保留源区，在独立目标完成核心治理与入口对齐，新会话凭目标文件接续。该目标未启用 Git。
- 原位兼容：已有工作区在覆盖前完整快照治理文件并验证隔离恢复，按清单核对实际共享来源和保护。真实新会话接手并完成获准的小文档任务，该现场通过用户验收。

早期中英文候选均已分别解包并核对入口。英文极简有章程落盘及首次重读样例，另有英文实例验证本地 Git 和一页入口说明。这些记录使用各自固定候选当时的状态值。新版英文状态的兼容性按该修订的定向复验取证。

另有一组跨宿主试验覆盖中文实例的只读接手。完整 Visualize／HTML 问卷、简图宿主交互、跨系统和宿主的组合矩阵、选装模块的实际业务运行及官方下载源仍有覆盖缺口。

真实工作区的共享接入及适用上位规则，按实际采用现场另验。模块材料按需采用；获取、跨区通信及无人值守必须满足实际能力和授权条件。
