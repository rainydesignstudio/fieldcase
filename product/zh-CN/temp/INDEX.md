# 临时层总索引

路径基准：本 INDEX 所在目录；根入口从根 INDEX 的 T 项定位。
维护归属：根维护者维护本索引；产物由明确的所属任务／工作区维护。
索引模型与引用：D:index-spec；身份与授权：根治理 §1–§2。

## 1. 存放、权限与读取

- 分类目录只作共用入口。实际产物进入下表声明的工作区、任务、库或批次路径，不把分类父目录当作任意可写目录。
- <工作区> 取已确认的归属名，<任务>／<批次> 取可辨识名称；已有合法归属优先复用，不为同一内容另开旁路。归属不明先报告，不擅迁移或清理。
- 索引登记只提供定位，不授予读取全部临时内容或改写别人的产物。读取按用户授权、任务范围和表内取用方式进行；体积为“—”的目录不整读、不递归取总大小。
- 按已批章程／任务范围、所选能力和真实用途建立必要分类或产物；本表只说明合法用途，不预建所有空分类、任务目录或空INDEX，不以目录存在证明工程完成。
- 临时件不因被登记成为治理依据。待审内容、固定候选和正式知识分清，只有按所属准入流程落入正式位置的内容才可当作已采用规范。
- 有 Git 时，T 产物排除，本区拥有的 T 总 INDEX 作为治理件纳入根仓。T 中 worktree 属其原仓，不能说 T 有了独立仓。
- 复用上级T时，本索引只作候选原件；现行入口及本区获准归属按上级索引，不创建第二套实际T或代改其总索引。
- 两种治理方向的采用原件、迁入来源副本和升级恢复快照由docs INDEX定位，属于比较／恢复依据；不当作可弃缓存，不在此递归复制。

### 2.1 等型暂存与正式归位

- 本区自有 T 中，待归位资料的正式落点已知时，以目标工作区根为路径基准。正式落点在一级目录（L1）下时，从该目录的实际名称起，将完整相对路径接在 T:cache 的实际入口下。例如 `materials/media/logo.png` 暂存为 `cache/materials/media/logo.png`。采用自定层目录时取实际名称，按需创建本次使用的路径。
- 根文件按获准的工作区归属暂存，例如将 `HANDOFF.md` 暂存在 `cache/<工作区>/HANDOFF.md`。复用上级 T 时，以共享索引的实际缓存入口和获准归属为准，在方案中写明暂存与正式路径的对应。原始件及获取工具按实际 T 入口和已采用的方法规范存放。
- 核对正式目标和内容范围，获准写入后按确认范围归位。按目标层协议同步受影响的索引和引用，并核对实物和入口。正式目标未定时，沿本次授权暂存，待目标确认后再归位。

## 3. 引用与配套维护

- T:audit#<工作区>/<任务>/ 等引用先由根 T 入口进入本索引，再按该行入口定位子路径。标识不随分类目录改名变化，实体迁移与本表及相关工具参数同批更新。
- 整理存量分类或移动已登记产物前，先拟当前路径、实际用途与留存条件、目标分类和落点，以及受影响的索引、引用及 Git 跟踪项。方案审定并获执行授权后，在该批范围内同步迁移文件和更新入口，再核对两者一致。
- 分类内确需局部定位时才建立子 INDEX，由上一级索引指向。已有批次清单或报告足以定位时沿用其入口。
- 分发缓存的局部 INDEX 只在实际取得完整资源后登记；内容须写模块用途、精确来源、兼容基线、依赖、配套修改和材料入口。下载不等于采用，config.modules 只记完成集成的模块。
- 按需创建的工作树、复制目录或临时实例必须写清固定来源和用途；不预建所有历史版本。正式消费的开发 worktree 复用原仓共同历史。
- 清理缓存不能删除已经采用的官方原件或现行配置，也不擅自清理他人会话。待归位资料、固定待审副本、唯一证据与恢复备份的清理须按其授权和保留条件办理。
- 新公共分类、归属和读取边界变更先拟稿；分类下普通任务批次增减不另算新增层，也不因此授予父目录写入权限。

权威：本索引为 T 分类、归属及存放的唯一来源；实际入口由根 INDEX 的 T 项定位。复核触发：分类、归属、读取、跟踪或清理边界变化。
