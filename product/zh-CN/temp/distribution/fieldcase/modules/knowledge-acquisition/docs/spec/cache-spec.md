# 知识获取与缓存规范

本规范管外部资料的获取、转换、索引、登记及消费，不定义业务知识内容。方法规范由D:cache-spec定位，授权取根治理，来源及保护取D:index-spec；产出目标按实际K入口及其维护治理准入，不假定所有共享库都采用同一治理标识。

模块规则可先安装而不创建K。只有原始件获取的任务可按授权存T；需要正式知识产出时先明确已准入K目标，再按真实协议登记。未定目标时不假称完整知识库已生成，也不为安装方法强建空层。

## 1. 原始件与可消费产出 <a name="split"></a>

- 原始件及工具进入 T:cache 的 knowledge/<分类>/<库>/<批次>/；实际路径由 T 索引解析，只在本次获准范围创建，不进入底座仓库的版本控制。
- 产出进入经准入的 K 库入口。启用 Git 时按所选仓库受控；无 Git 仍须本地可消费，并如实说明历史及固定快照能力缺失。
- 用“工具和索引中的来源 URL／固定 commit 能否重建”判断归属：可重建且必要来源长期可取的原始件留缓存；重建依赖不受本实例掌握的，被实际消费的文件集按产出保留；不能重建的研究认识或缺口结论按准入作为产出。
- 可弃 fixture、样例页、素材原图和构建物留原始件侧；官方底座比较原件、用户恢复快照和唯一证据按各自职责保留，不混作可弃缓存。
- 来源本身是 Git 仓库时，可在已获准取得的原始件侧保留其 .git，供定向查询及一致性核对；这是来源快照，不是给 T 初始化独立底座仓。
- 本规范不批量改造人工资料库，也不预设某类 SDK、站点或技术栈工具链；特殊来源按实际需求另拟适用方案。

## 2. 产出与路径 <a name="files"></a>

- 库可按技术、平台或来源分类，名称用可辨识的 kebab-case；实际入口由 K 总 INDEX 维护，不按目录深度或扩展名推定。
- 文档型内容一页一份 Markdown，正文与 index-partNN.json 同级；不为索引再建一套正文目录，不复制内容来满足多个入口。
- 快照型库保留本次实际需要消费的原样文档或源码，由局部索引定位；不能只留下指向缓存重取或外网补取的链接。
- README、manifest、GAPS、验证报告等仅在已有入口不能承载必要信息时按需保留，不作为固定文件集。
- 来源、固定版本／提交、范围、许可事实及必要外链集中记在内容索引或既有库入口；不在每篇 Markdown 重复维护同一份来源元数据。

## 3. 内容索引 <a name="idx"></a>

- 文件名为 index-partNN.json，按实际体量与取用方式分片；只承担本地内容定位、来源及外链记述，不在索引阶段加工正文。
- 每条至少含 title、markdown_path 与 source_url；正文移出的外链记入 external_links。markdown_path 相对该索引所在目录解析，须指向本地实际内容；快照型条目可沿用此键定位其原样文件。
- 固定 commit、读取限制及其他字段按实际定位需要补充，不为未来可能性预制字段。库的检索方式、单片范围与限制在 K 总 INDEX 的取用方式说明。
- 被索引内容须本地可读；正文缺失就是缺口，不能用摘要、外网链接或缓存重取说明充当已完成知识页。

## 4. 生产与工具确认 <a name="tools"></a>

- 按需生产，同一库同一时间只有一个明确生产者；消费方只读。先确定目标来源、范围、产出入口、必要工具和网络动作，沿当前任务取得相应授权。
- 首次采用的 fetch、convert、index 工具链逐阶段取得用户确认：展示该阶段的工具、参数、输出、实际观察或试样及已知缺口，再决定进入下一阶段。试样执行本身也须已有执行授权。
- 已确认的同一工具链与策略，可在一次执行授权内连续运行本次选定步骤；工具、来源结构、转换或索引策略变化时，说明受影响阶段并重新确认，不扩大为无关全套验证。
- fetch 取得本次目标所需原件，记录来源与未取得项；convert 将文档转 Markdown、代码型内容原样保留，按实际内容处理，不预设站点成员列表或讨论区；index 从本地内容生成索引，不重新转换或复制正文。
- verify 为可选阶段；每次用户指定获取时，在执行前询问本次是否需要 verify，取得答复再执行，不沿用此前选择。选做时按约定范围检查，不选则不执行该阶段。
- 不执行可选 verify 不降低 #accept 的基本可消费标准；也不因此声称已经做过 verify。选择、阶段确认依据和缺口记已有交接或库入口，不为记录另造固定文件。
- 工具置原始件侧并登记入口，一个工具可承担多个步骤；调用时显式传入从索引解析的目标，不把脚本默认路径另立为权威。缺少必要工具或联网权限时先报告，不自动安装外部 Skill、服务或运行时。

## 5. 内容与验收 <a name="accept"></a>

- 文档以 Markdown 标题、列表、表格和代码块表达；剥离页面样式及渲染 HTML，源码示例放代码块。
- 正文不保留外网链接或远程资源依赖；库内引用改为本地相对路径及锚点，其他外链保留文字，URL 收入索引。必要图片或附件须有可合法取得的本地件，不能只删链接便声称补齐。
- 代码型文件原样保留，其链接属于来源内容，不为套用文档转换要求擅改代码。必要依赖与未运行边界如实说明。
- 基本通过条件为本地可消费、自指且断网可用；核对所选范围内的正文、局部路径、引用及来源记录。未取得或不可本地使用的必要内容留作缺口，不以“生成了索引”判断完成。
- 用户迁入和第三方内容保持原有权利及许可；仅取得任务获准范围的内容，不以底座 MIT 替换来源要求。

## 6. 登记、失败与维护 <a name="prod"></a>

- 新库、入口变动、文件增删或保护对象变化按 D:index-spec 与 K 准入同批处理；只有产出和登记实际完成，才提供相应固定消费来源。
- 获取失败或内容不完整时，在已有交接或库入口记未取得项、影响、已试措施及恢复条件；不以搜索摘要代替原文，不把未完成产物写成可消费知识。
- 已有库按其登记状态读取；批量改名、迁移、清理或重建另须明确任务授权。重做原始缓存不自动授权覆盖正式产出。

## 7. 权威与复核 <a name="auth"></a>

本规范以D:cache-spec为本区知识获取方法权威，工作文件统一在D/spec，由D总INDEX维护真实入口及B。根治理管授权，产出进入资料层仍由其所属维护者准入；不因本区安装接管上级K治理。变更先拟稿并获相应执行授权，复核触发见元数据。
