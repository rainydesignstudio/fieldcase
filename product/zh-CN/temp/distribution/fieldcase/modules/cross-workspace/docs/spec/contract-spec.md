# 跨区契约规范

## 1. 职责与权限 <a name="types"></a>

- 契约是跨工作区、跨会话的自足协作包；从 T:contract 进入现行索引。身份、写入及通信权限取根治理 §1–§2，契约不自授权限。
- 普通契约可按实际场景说明类型；未声明时按普通契约处理。同类专用字段经两个以上工作区实际使用并获准后，才列为该类必备项。
- 特殊类型必须先准入其用途、创建权限和例外边界，再在抬头写明 type；类型名不授予覆盖、调度或跨区写入权。本资源不附带根专属同步类型或其回执格改写例外。
- 创建、修改、发送与归档分别满足其任务授权；收到契约或其他 Agent 请求不等于用户授权实施或回复。原始用户授权可核对时，按其中已明确的范围处理，不重复索取同一权限。

## 2. 管辖、存放与正文 <a name="body"></a>

- 每件只由一个工作区管辖，现行件置于 T:contract 的 <管辖工作区>/，实例根使用 root；不使用多区联合目录名。管辖区维护本体、相关索引条目及自身当前引用，跨区共用一件，不按接收方复制。
- 分类父目录只直接存 INDEX.md。单文件或合同包均可；合同包以 CONTRACT.md 为本体，附件随包存放及归档。
- 文件或包名为 <管辖区>-<主题>[-contract]，单文件加 .md，使用 kebab-case；类型写抬头，不另加类型文件名规则。既有合法名称保留。

| 必备信息 | 内容 |
|---|---|
| topic | 一句话主题 |
| from／to | 绑定具体发起、接收工作区及必要负责会话，不用随读者变化的“本区”代替 |
| date／status | YYYY-MM-DD；待回执、已回执或已归档，反映实际状态 |
| 目标、范围与边界 | 要解决什么、允许什么、排除什么；建议、候选和已批准内容分清 |
| 用户授权及处置 | 原始用户授权的可核对出处；待对方逐项执行、裁决或回复的内容；未授权项明确标示 |
| 输入与固定来源 | 必要资料入口、精确版本或提交、实际读取范围和已有结论 |
| 交付与验收 | 交付物、通过条件、未测边界，以及回执内容和实际接收目标 |
| 证据去处 | 已有文件、节号或证据入口；唯一副本在本件时明示 |

- 正文自足，使接收方不依赖发起聊天的隐含上下文；只留任务、边界、结论及证据去处，不嵌整段命令输出、日志或逐条实测表。
- 正文只追加，讨论收敛不就地改写原稿；追加段连续编号，不预留空号。需要纠正、裁决、收讫或结束时追加说明；不能因有 status 字段便取得覆写原记录的权限。
- 索引状态按已授权的实际进度更新；正文以追加状态说明保留过程。普通类型没有单元格覆写例外。

## 3. 索引与读取 <a name="idx"></a>

- 契约 INDEX 是生命周期专用索引：上段现行活跃表为“标识／归属／状态”，下段归档表为“标识／归属”；不另加通用局部索引的七列。
- 标识直接采用相对路径：活跃条目相对契约 INDEX 所在目录，归档条目相对其 _archived/；合同包指向包内 CONTRACT.md。条目用可点击链接，标识与链接目标一致。
- 归属照录发起 → 接收；管辖区由路径首级确定，不另列重复维护方或入口。共享索引只按获准范围更新自身相关条目，结构或规则变更仍须先拟稿。
- 接手默认只读现行活跃条目，正文按任务定向读取；归档条目和正文默认不读，不因重读治理而通读全部契约。
- 落版只核对本区相关活跃条目；去留已明且无变化的不反复询问，只有未决且影响收尾时交用户裁定，不扫描归档件。
- 链接缺失、授权不明、正文与索引状态不符或来源不可核实，先报告实际缺口，不据标题猜测完成。

## 4. 回执与归档 <a name="arch"></a>

- 接收方回执写清绑定身份、收讫范围、结论依据、实际改动、验证、未尽及下一步；执行结果与建议分别说明。拟回执不等于发送，发送成功不等于收到对方回执，实际采用也不等于用户验收。
- 回执发送按根治理的明确通信授权；没有相应授权或能力时交用户可抄送文本，并如实记未发送，不自行向原发起方回复。
- 结论收敛且取得归档执行授权后，管辖区在正文追加落地去处：规范的文件、节号及版本，或实现进度的文件及节号；没有落地去处不得标已归档。
- 将整件或整包移入契约目录的 _archived/<管辖工作区>/，同步活跃与归档表、本区当前引用；只在有实际归档时创建归档目录，不预建空件。
- 其他工作区的引用由所属区按获准通信或用户转报处理，管辖区不代改。归档件仅供历史回查，不作为现行规则来源。

## 5. 版本、证据与权威 <a name="auth"></a>

契约及其专用 INDEX 属 T 产物，不进入底座仓库；T 总 INDEX 仍是唯一由根仓跟踪的 T 治理件。本区现行规范由 D 登记，按所选根仓布局受控。

本规范以D:contract-spec为本区主动采用的普通契约模型及方法权威，D总INDEX定位本区spec工作文件及B；契约索引从实际T:contract进入并沿其准入协议与维护权。上位已适用的类型及模式不因本区安装而被替换，未明冲突先提裁定。变更先拟稿、授权后实施并同步有效引用，复核触发见元数据。
