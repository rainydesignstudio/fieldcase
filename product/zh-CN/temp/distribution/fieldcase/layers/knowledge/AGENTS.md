# 知识库层治理

## 1. 归属与入口

- K仅在实际知识库需求下采用，由根INDEX的K项进入；可本区自建、引用已有共享库或按批准清单导入，不为最小工作区强建空层。采用K不创建Agent，维护者由用户指定。
- 本区完整管理规范统一在D，不装入本层；操作模式和权限取根治理，索引／来源／保护取D:index-spec，版本与消费记录取D:handoff-spec。本文件只维护K知识库的职责差异。
- 自建K由本层INDEX维护资料、工具及必要局部索引；接入外部K保留其真实协议、版本、位置及所有权，不覆盖提供侧INDEX或AGENTS。提供侧规范已适用的效力沿原权威，不因归在K自动降为纯参考。
- 同时只有一个明确写入持有者；接手核授权及既有改动，不覆盖、代暂存或代提交他人内容。可访问、发现问题或收到消息都不构成写权。
- 导入先明确来源、范围、目标与许可，默认保持源区；实际复制、移动、仓库或引用调整须属于对应任务授权，完整授权已经包含的动作不重复申领，不以“接入知识库”删除源目录或改外部仓。原业务库及其有效引用不因D迁位被清空。

## 2. 内容准入与生产

- 每项正式知识须有本地可消费内容、真实入口、必要来源和使用限制，不以搜索摘要或外网重取链接代替实际知识页。原结构和局部协议能用则保留，结构改造先拟方案。
- 内容、索引、实际B与有效引用同批维护，稳定标识不随位置改变；受保护治理／规范目录须有完整成员及逐文件B，不给每个普通目录预建空INDEX。
- 同B不证明正文未改，修改仍需准入及来源核实；登记未变不强造INDEX差异，来源或正文缺失不冒称通过。
- 可重建原始件和工具按T缓存保存；不可重建的研究认识、缺口结论及实际依赖文件按准入保留为知识内容。人工知识库不强套自动抓取工具链。
- 采用知识获取方法时从D:cache-spec取生产、首次工具链确认及每次可选verify规则。模块规则可先就位；只获取原始件可按本次授权存T，要形成正式知识产出时须先有已准入的K目标。安装方法不自动联网、装工具或取得共享写权。
- 用户及第三方内容保持其权利和许可；底座许可不自动覆盖资料。必要许可事实随来源保留，不复制未获授权资源。

## 3. 消费与贡献

- 默认策略取config，实际K来源在消费区HANDOFF的一处资料表登记。新任务或明确切换时固定来源，同任务恢复同一提交／可靠副本；INDEX、成员与正文来自同源，不跟移动分支静默更新。
- 本区无仓与来源无Git分别判断；外部已有固定来源可正常按其保障消费，本地现状没有历史保障时如实说明。需要目录展示时按获准T路径展开，不切换维护者工作树或预造所有版本。
- 开发与正式、候选比较与实际试用分别登记；试用同处补范围和原依赖。正式目录稳定与T worktree开发须同仓共同历史、分支能力及授权，无Git或直接main不宣称具备。
- 无正式K写权的贡献先在自己的获准T归属形成候选，再由有权限维护者审阅，配套与索引完成并形成真实固定来源后才供消费；审阅不等于准入，层更新不让所有消费者自动升级，不代改消费区交接或发送消息。

## 4. 仓库、版本与修缮

- K 的受控范围按获准清单和实际所属仓核对，外部仓不重置。layer_version 只在本层 INDEX 记录。本区K不承载D规范，不因D迁位擅自合并、删除或重建既有层仓。
- 内容身份取D:index-spec#identity；新层无可靠固定基线时为development，明确准入及固定定位才为baseline，实际落版才为released，不替代工作区三态。已供消费提交保持可达，固定标签不移动。
- 提交按路径，版本递增、首版同号、主干起点、落版及历史取根治理与D:handoff-spec。T worktree属原仓，不构成T独立层仓。
- 来源、类型、入口、成员或B偏差按D:index-spec报告；消费方不直接改B消错。维护者在权限内查明原因、拟修、落实并核验；不能拿旧INDEX证明新正文。
- 排障例外沿根明确授权，enforce=false不使缺来源、缺文件或缺权限有效。修缮和层变更记已有交接；外部引用及pin由所属方按权限维护。

权威：K:knowledge-governance，由实际K总INDEX定位；复核触发见元数据。未采用的本件只作固定分发原件，不自动生效。
