# 材料层治理

## 1. 归属与权限

- 本层由根 INDEX 的 M 项定位，工作模式与实施授权取根治理 §1–§2。维护者由用户指定，未另指定时由根维护者负责；启用 M 不创建 Agent。
- 本层 INDEX 是生产材料的唯一总入口；索引、固定来源和读取取 D:index-spec，版本及消费记录取 D:handoff-spec。
- 同时只有一个明确的写入持有者；生产任务先明确对象、可改范围、用途、来源和交付判据。接手核对已有改动，不覆盖、暂存或提交他人内容。
- 消费方只读获准材料；引用、下载、生成或收到建议不构成正式入库和修改授权。候选内容先留在该任务已获准的 T 归属路径，准入后由有权限维护者纳入本层。

## 2. 生产与准入

- M 保存品牌、内容、设计及其他实际生产材料；未定稿素材、生成中间件和可弃转换物按 T 用途存放，参考快照按 R 职责处理，不因扩展名代替归属判断。
- 入库或替换前说明来源、用途、必要的使用条件、实际缺口及受影响引用；用户自有内容与第三方内容保持各自权利。联网获取、生成服务及外部发送另须相应授权。
- 治理、规范及索引结构先交完整拟稿／差异和 MVD 量化；材料正文按该任务获准方案实施。材料修改不自动改变根治理、业务需求或其他工作区文件。
- 正式材料须本地可用、入口可达，必要来源和限制由已有索引或材料入口承载，不为记录预建固定附册；空层不预造品牌、业务资料或示例项目。
- 实体、所属索引、实际 B 与有效引用同批核对；同一对象迁移保留标识。删除、迁移和清理须在明确范围内办理，不将旧定稿静默改成新版本。

## 3. 仓库、交接与维护

- 本区启用 Git 时，M 层治理及总 INDEX 随所属区仓跟踪，材料正文默认留在仓外，按所属任务的明确授权维护。正文纳入版本控制须有已准入的路径清单。版本与分支沿实际仓和已准入规则，layer_version 只在本层 INDEX 记录。
- 提交按明确路径，先核对归属；无 Git 如实说明能力边界。稳定定位和已供消费的提交保持可达，不能借追加或清理使消费记录失效。
- 任务事实、未尽和证据去处记负责会话既有 HANDOFF；不另建材料层专属交接，也不代改消费区记录。层更新不自动切换现有消费者来源。

## 4. 权威与复核

本文件以 M:materials-governance 为本层生产、准入及维护差异的唯一权威；实际入口由 M INDEX 维护。变更仍须相应准入与执行授权，复核触发见元数据。
